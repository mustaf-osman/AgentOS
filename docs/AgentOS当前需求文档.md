# AgentOS 当前需求文档

版本：v1.0  
更新时间：2026-10-20  
用途：产品开发、当前前后端接入、后续 AI 交接。  
优先级：本文件按用户最新明确要求整理。与早期“森林绿界面”“仅聊天双栏界面”等描述冲突时，以本文件及用户之后的要求为准。

## 1. 产品定位

**AgentOS 是一个通过自然语言直接操控电脑的智能体产品，最终以用户手中的 ESP32 小硬件作为交互入口。当前阶段先完成电脑端软件。**

用户说出目标，AI 理解任务、调用真实工具、观察执行结果，再推进下一步。科研与学习是比赛重点场景，电脑操作是产品的核心能力。

一句话说明：**把需求说给手中的设备，让 AI 帮你在电脑上把事情做出来。**

### 比赛主题

对应阿里云特别赛题：**基于 Qwen 大模型的科研提效：认知增强与研发范式革新**。

围绕“提出问题 → 获取资料 → 分析与执行 → 结果复核 → 成果交付”组织科研体验，突出自然语言、电脑工具与未来硬件入口之间的协同。

### 当前阶段的边界

- 完成电脑端软件及其真实后端接入，提供 Windows 桌面运行方式。
- 保留 ESP32 扩展位置，设备状态必须反映实际连接情况。
- 按用户此前要求，本轮不连接、不扫描、不烧录 ESP32；硬件入口是产品方向，不作为本轮已接入能力展示。
- 软件应让用户能够直接聊天下达目标，避免要求用户先配置复杂流程才能提问。

## 3. 本轮开发目标

**把现有 AgentOS 后端接到指定前端，使页面上的入口使用真实数据、保存真实状态，并能触发实际任务。**

这轮工作是前后端连接和必要接口补齐。现有 Node 服务、SQLite 数据、本地研究文件、Qwen 兼容接口和 Electron 桌面架构继续使用。

## 4. 功能需求

### 4.1 聊天与任务

| 编号 | 功能 | 必须达到的行为 |
| --- | --- | --- |
| CHAT-01 | 新建任务 | 建立独立会话，不把新任务追加到固定演示会话。支持原有 Ctrl/Cmd + K 入口。 |
| CHAT-02 | 自然语言聊天 | 将用户消息发送至当前配置的真实模型，显示实际回复和错误，不返回固定模拟文案。 |
| CHAT-03 | 连续追问 | 使用当前会话已有上下文；切换会话后不混入其他任务内容。 |
| CHAT-04 | 最近任务 | 从本地持久化记录加载标题、更新时间和选中状态，刷新后仍保留。 |
| CHAT-05 | 重命名 | 修改真实会话名称，刷新、切换后仍有效。 |
| CHAT-06 | 停止任务 | 用户能够停止当前执行；保留已有输出、文件和执行记录。 |
| CHAT-07 | 回收站 | 对话与文件可以移入回收站并恢复；本轮不需要永久清空。 |
| CHAT-08 | 输入体验 | Enter 发送、Shift + Enter 换行，兼容中文输入法；失败时保留未成功发送的内容。 |
| CHAT-09 | 状态反馈 | 显示真实的思考、执行、等待确认、完成、失败、中止和待复核状态。 |

### 4.2 研究空间

- 左侧“研究空间”入口展示真实空间，支持创建、选择和修改名称。
- 各空间的任务、文件、来源和分析结果分别保存。
- 当前选中的空间和会话可以在刷新后恢复。
- 任务运行期间遵守现有并发约束，不允许通过切换界面绕过文件或设置修改限制。

### 4.3 文献库与参考资料

- “文献库”和右侧“参考资料”展示实际检索或阅读得到的条目。
- 保留来源标题、URL，以及接口实际提供的作者、日期、DOI、摘要等信息。
- 区分“检索到文献元数据”和“已经阅读正文”，不能把两者混为一谈。
- 可查看条目详情，打开原始来源；已保存正文时可查看对应本地文件。
- 当前后端文献搜索使用 Crossref，不保留截图中 Google Scholar、arXiv、Web of Science 的虚构结果计数。
- 某来源没有接入时不能显示为已接入；未来添加来源需有实际接口或工具支持。

### 4.4 数据集与结果

- “数据集”入口展示当前研究空间的真实 CSV、JSON 等数据文件。
- 可导入数据、查看文件信息与内容预览，并把文件加入对话供 AI 分析。
- 右侧“数据结果”展示真实分析输出；图表来自实际生成的文件，表格来自实际数据。
- 图表、表格、摘要的切换使用对应的真实内容；缺少某类结果时显示明确空状态。
- 导出的 CSV、报告和图片必须与当前实际结果一致，不能导出演示数据冒充分析成果。
- 运行代码和实验应保留输入、参数、脚本、输出及相关记录，便于复核。

### 4.5 附件与产出文件

- 输入框附件入口实际上传至当前研究空间，不仅显示文件名。
- 用户可选择已存在的文件附加到本轮任务，模型能够定位到真实文件路径。
- 右侧“产出文件”显示空间中的真实文件及大小、更新时间。
- 支持文本、Markdown、CSV、JSON 和图片的适用预览，PDF 可下载或交给阅读工具处理。
- 支持下载单个文件，使用已有能力编辑文本文件、保留修订信息并防止覆盖冲突。
- 支持导出当前研究空间 ZIP。
- 文件移入回收站后可以恢复，恢复时检查同名冲突。

### 4.6 任务进度与运行记录

- 右侧“任务进度”来自后端实际任务、执行计划和工具事件。
- 展示实际步骤名称、等待/进行/完成/失败状态及真实耗时。
- 只有存在明确执行计划时，按已完成步骤计算计划进度；没有计划时展示状态，不编造百分比。
- 当前执行内容根据真实工具调用更新，保留成功、失败和错误说明。
- 支持查看已有截图与执行结果；截图不能代替实际操作后的核对。
- 页面通过后端事件推送更新，不要求用户反复刷新；连接中断时给出恢复提示。
- 用户展开的详情、阅读位置和输入内容不应因后台更新反复丢失。

### 4.7 工具箱与电脑操作

- 工具箱展示后端实际提供的工具与环境状态。
- 使用现有文件、PDF、公开文献、网页、Python、研究浏览器和 Windows 操作工具。
- 电脑操作包括已有窗口/控件读取、应用打开、窗口切换、输入、按键、鼠标及截图适配。
- 执行代码、命令和有确认要求的电脑动作时，在界面内显示具体内容，由用户允许或拒绝。
- 操作后以实际观察和工具结果判断状态；失败、拒绝、超时和中断必须明确呈现。
- 现有研究浏览器的能力以公共页面读取和受限交互为准，不因接入前端而擅自扩大为登录、外部提交或付款。
- ESP32 显示实际未连接状态，本轮不启动设备操作。

### 4.8 模型与设置

- 设置入口管理真实模型服务地址、对话模型、视觉模型、API Key 及已有工具权限。
- 兼容当前 Qwen 接口配置与已授权的服务商接入方式。
- API Key 以密码形式输入，读取配置时只显示是否已保存，不回传明文。
- “检查连接”触发真实接口请求；只有真实成功才能显示连接正常。
- 设置保存后持久化，刷新后仍有效；运行任务时遵守后端修改限制。
- 原有配置和密钥继续在本地保存，不写入需求文档、交接材料或前端源码。

### 4.9 联网搜索、研究模式与深度分析

- “联网搜索”对本轮任务实际生效；关闭时同时限制相应后端工具，不能只有按钮颜色变化。
- 任务级开关不能绕过应用全局权限。
- “研究模式/快速模式”作为真实参数传给后端，改变任务组织和输出要求。
- “深度分析”实际影响本轮任务的方法比较、证据对照和结果复核要求；不能只弹出已开启提示。
- 每轮任务保存使用的模式和角色信息，便于回看。

### 4.10 智能体团队

- 此入口提供可选择的研究角色，例如研究助理、文献研究员、数据分析员、结果复核员和电脑操作助手。
- 角色的说明和任务侧重点实际传入执行过程；支持创建自定义角色及持久保存。
- 当前后端基础是单一模型的工具执行循环。角色切换与真正的多智能体并行协作必须明确区分。
- 本轮先把角色管理与任务角色选择做实，不把单模型切换角色描述成已经具备独立多智能体并行研究或独立验证。

## 5. 数据与交互原则

1. **真实执行**：AI 回复、任务、来源、文件和图表均来自实际接口或本机结果。
2. **真实状态**：工具返回失败时不显示成功；模型自述“完成”不等于已经完成操作。
3. **本地留存**：会话、事件、资料和成果在现有研究空间保存；应用重启不丢失已有记录。
4. **来源清楚**：区分用户上传、网页正文、文献元数据、计算结果和硬件实测。
5. **操作可控**：保留已有权限、逐次确认、停止和超时机制，不为界面接入跳过确认。
6. **错误可理解**：鉴权、限流、连接、工具缺失、权限和文件冲突等问题给出可理解提示。
7. **视觉保持**：真实内容替换演示内容，沿用指定前端设计。

## 7. 功能交付的判断口径

以下用于说明完成标准，不代表已经执行过对应测试：

- 输入问题走真实聊天接口，能够显示后端回复或真实错误。
- 切换、重命名、回收、恢复和空间选择使用持久化数据。
- 上传的文件实际存在，下载和预览指向该文件。
- 进度、来源、数据和成果来自当前实际任务或明确标注的研究空间。
- 模式和联网开关落实到后端执行参数。
- 操作确认、拒绝、停止和错误反馈仍可通过新前端表达。
- 不出现固定模拟回复、虚构论文数量或写死的进度图表。
- 指定前端的整体外观保持一致。
